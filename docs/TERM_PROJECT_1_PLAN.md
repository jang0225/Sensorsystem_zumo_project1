# Term Project 1 진행 계획

## 1. 과제 목표

Zumo 로봇이 사용자 버튼 입력 후 출발하여 다음 임무를 자율적으로 수행하도록 구현한다.

1. 구간 1의 약 16 cm 폭 곡선 차선 내부를 주행한다.
2. 구간 2의 가운데 검은 선을 따라 고정 장애물과 승강식 장애물을 통과한다.
3. 회색 체크포인트를 인식한다.
4. 체크포인트에서 방향을 전환한다.
5. 구간 2 중앙선을 반대로 주행하여 합류 지점을 직진하고, 구간 2 위쪽 종료선을 통과한 뒤 정지한다. 구간 1로 돌아가지 않는다.

2026-11-04 정정: 초기 계획의 ‘출발선 복귀’는 잘못된 해석이었다. PDF의 +20 위치와 시뮬레이터의 종료 판정은 모두 구간 2 위쪽 출구를 가리킨다. 시뮬레이터는 체크포인트 획득 후 도면 좌표 `py < 40`, `225 < px < 255`에서 복귀 점수를 부여한다.

코스의 치수와 센서 반응은 실제 설치 상태에 따라 조금 달라질 수 있으므로, 시뮬레이터에서 기능을 먼저 검증한 뒤 실제 코스에서 임계값과 속도를 조정한다.

현재 개발 기준은 사용자가 선택한 제공 시뮬레이터의 채점 방식이다. 차량 중심만 차로 안에 두는 것으로는 충분하지 않으며, 좌우 트랙의 접촉 판정 지점이 경계선에 닿지 않도록 구성한다. 실제 수업에서 안내한 중심 기준은 추후 실물 시험에서 별도로 적용한다.

## 2. 채점 조건과 개발 우선순위

| 항목 | 점수 |

- 차선 접촉은 1회당 1점 감점이며 최대 10점까지 감점된다.
- 장애물 충돌은 1회당 5점 감점이며 최대 15점까지 감점된다.
- 한 번의 시도는 최대 1분 30초이고 총 두 번의 시도 중 높은 점수가 반영된다.
- 로봇을 손으로 만지거나 로봇이 코스를 벗어나면 해당 시도가 종료된다.
- 시간 점수는 전 구간을 완주한 경우에만 주어진다.

안정성을 우선하되 90초 시간 예산을 함께 관리한다. 부분 구간은 저속으로 확인하고, 전 구간에서는 회전과 차단기 대기를 포함한 시간을 측정한다. 시뮬레이터에서 모터 명령 120은 약 10.6 cm/s이므로 약 8.7 m 경로의 단순 주행만 약 82초가 걸린다. 초기 통합 속도는 200 부근(약 22 cm/s)에서 시험한다. 실제 속도는 배터리와 마찰에 따라 달라지므로 실측한다.

2026-11-04에는 `main.cpp`에 아래 상태기계와 주행 제어를 구현하였다. 위 항목은 원본 설명이며 현재 구현 상태를 뜻하지 않는다. 현재 코드는 시뮬레이터용 초기 구현이고, 실제 로봇의 보정과 주행 검증은 남아 있다.

### 3.3. 제공 센서 및 구동 함수

- `setSpeeds(left, right)`: 좌우 모터를 `-400`부터 `400`까지 제어한다.
- `irUpdate()`: 6개 IR 센서를 갱신한다.
- `irValue[0..5]`: 왼쪽에서 오른쪽 순서이며, 흰색은 0에 가깝고 검은색은 1000에 가깝다.
- `irBlack[0..5]`: 각 센서가 검은색을 감지했는지 나타낸다.
- `usUpdate()`: 초음파 거리를 갱신하며 최근 5회 값의 중앙값을 `usCm`에 저장한다.
- `usCm == 999`: 유효한 초음파 반사 신호가 없음을 의미한다.
- `buttonPressed()`: 사용자 버튼을 누른 순간 한 번만 `true`가 된다.
- `zumoBegin()`: 모터, 센서, 버튼 및 인터럽트를 초기화한다.

원본의 IR 보정값은 임시값이다. 구현한 `main.cpp`에서는 `SIM_WHITE/BLACK`과 `REAL_WHITE/BLACK`을 분리하고 `SIMULATION`으로 선택한다. 실제 보정값을 측정하기 전에는 `REAL_CALIBRATION_READY`를 켜지 않는다. 실제 모터 편차, 제어 계수 및 IMU 종류도 별도로 확인한다.

## 4. 권장 상태기계 구조

제공된 상태를 그대로 사용해도 되지만, 출발 과정과 복귀 과정을 명확하게 구분하기 위해 다음과 같이 세분화하는 편이 디버깅에 유리하다.

```text
WAIT
  -> LANE
  -> ALIGN_JUNCTION
  -> TURN_IN
  -> OUTBOUND
  -> ENTER_PAD
  -> PAD_STOP
  -> UTURN
  -> LEAVE_PAD
  -> RETURN
  -> FINISH

OUTBOUND / RETURN -> BARRIER -> 대기 전 상태
센서 오류 / 사용자 중지 / 시간 초과 -> FAULT
```

| 상태 | 역할 | 다음 상태로 넘어가는 조건 |
| --- | --- | --- |
| `WAIT` | 정지 중 자이로 편향 보정 | 보정 완료 후 사용자 버튼 입력 |
| `LANE` | 구간 1 곡선 차선 내부 주행 | 마지막 직선에서 횡방향 중앙선 검출 |
| `ALIGN_JUNCTION` | 센서보다 뒤에 있는 차체 중심을 중앙선에 정렬 | 짧은 전진 완료 |
| `TURN_IN` | 오른쪽 90도 회전 | 자이로 목표 각도 도달 |
| `OUTBOUND` | 가운데 검은 선 추종 | 장애물 또는 회색 패드 감지 |
| `BARRIER` | 예상 차단기 앞에서 정지 | 초음파로 닫힘 확인 후 열림이 유지됨 |
| `ENTER_PAD` | 차체를 패드 안으로 감속 진입 | 패드 확정 후 추정 5.5 cm 전진 완료 |
| `PAD_STOP` | 양쪽 모터 명령을 0으로 유지 | 700 ms 경과 후 유턴 시작 |
| `UTURN` | 약 180도 방향 전환 | 자이로 목표 각도 도달 |
| `LEAVE_PAD` | 회색 패드를 벗어나 중앙선 재진입 | 넓은 패드 패턴 해제 |
| `RETURN` | 중앙선을 따라 위쪽 출구로 직진 | 충분한 복귀 주행 후 선 끝 확인 |
| `FINISH` | 모터 정지 | 종료 |
| `FAULT` | 이상 상황에서 모터 정지 | 리셋 후 원인 확인 |

상태 전환은 한 번의 센서값으로 결정하지 않고 여러 번 연속으로 같은 조건이 만족될 때 확정한다. 모든 대기는 `delay()` 대신 `millis()`를 이용하여 구현한다.

### 5.2. 2단계: IR 센서 보정

각 센서에 대해 흰 바닥, 검은 테이프, 회색 체크포인트의 원시 측정값을 여러 번 기록한다. 시뮬레이터의 값은 실제 측정값을 대신하지 않는다.

1. 로봇을 흰 바닥에 놓고 각 센서의 원시값을 측정한다.
2. 로봇을 검은 테이프 위에 놓고 같은 방법으로 측정한다.
3. 순간적인 이상값보다 반복 측정의 중앙값 또는 안정된 대표값을 사용한다.
4. 측정값을 `irWhite[6]`, `irBlackUs[6]`에 센서별로 입력한다.
5. 경계 판정 임계값 `IR_GO_BLACK`과 `IR_GO_WHITE`가 흔들리지 않는지 확인한다.
6. 회색 패드 값의 범위를 따로 측정하여 패드 판별 조건을 정한다. 검정 판별용 600 임계값을 그대로 사용하지 않는다.

### 5.3. 3단계: 구간 1 곡선 차선 제어

구간 1은 검은 테이프 두 줄 사이의 흰 영역을 따라가는 문제다. 검은 선을 중앙에 두는 일반적인 라인 추종과 제어 목적이 다르다.

- 왼쪽 센서가 검은 경계에 가까워지면 오른쪽으로 조향한다.
- 오른쪽 센서가 검은 경계에 가까워지면 왼쪽으로 조향한다.
- `irBlack`만 사용하면 늦게 반응하므로 `irValue`의 연속값과 100~200 부근의 약한 경계 반응도 활용한다.
- 직선에서는 자이로로 방향을 유지하고, 곡선에서는 미리 정한 회전 성분에 IR 보정을 더한다. 코스 순서는 직선 → 왼쪽 180도 곡선 → 오른쪽 180도 곡선 → 직선이다.
- 시뮬레이터는 IR 바깥 센서가 중심에서 4 cm, 트랙 가장자리는 4.25 cm이므로 센서가 검정을 확실히 볼 때는 접촉이 이미 일어날 수 있다. 연속값 제어만으로 무접촉이 보장되지는 않는다.
- 실제 로봇의 추가 바깥 센서는 가능한 개선안이지만, 기본 시뮬레이터에서는 추가 센서 성능을 검증할 수 없다.

제어량의 출발점은 다음과 같이 구성할 수 있다.

```text
leftRisk  = 왼쪽 센서들의 경계 접근 정도
rightRisk = 오른쪽 센서들의 경계 접근 정도
error     = leftRisk - rightRisk
correction = curveFeedForward + Kp * error + Kd * filteredDerivative(error)

leftSpeed  = baseLeft  + correction
rightSpeed = baseRight - correction
```

현재 구현은 직선 기본 명령 200, 곡선 기본 명령 190을 사용한다. 곡선을 일정한 조향량으로 돌 때는 접촉 2회가 발생했으므로, 제공 코스 중앙 경로를 가로 반경 40 cm, 세로 반경 52 cm인 타원으로 보고 자이로 방향에 따른 곡률을 계산하도록 바꾸었다. 타원의 곡률에 맞춘 선행 조향에 IR 기반 PD 보정을 더한다. 미분은 실제 제어 간격으로 나누고 필터링하며 I 항은 사용하지 않는다. 최종 8회 시험에서는 차선 접촉이 없었다.

선행 조향은 알려진 코스 형상, 트랙 간격 8.5 cm 및 모터 모델을 이용한다. 펌웨어가 시뮬레이터의 실제 로봇 위치나 채점 변수를 읽는 방식은 아니다. 실물에서는 곡률, 마찰, 모터 편차가 달라질 수 있으므로 이 모델도 보정 대상이다.

완료 기준: 시뮬레이터에서 구간 1을 5회 연속 통과하고, 실제 코스에서 낮은 속도로 차선 접촉 없이 통과한다.

### 5.4. 4단계: 구간 2 가운데 선 추종

구간 2는 가운데 검은 선을 로봇 중앙에 유지하는 일반적인 라인 추종으로 처리한다.

진입 시에는 동쪽으로 달리다가 세로 중앙선이 IR 배열 전체에 걸리는 패턴을 확인한다. 곧바로 돌면 차체 중심이 중앙선에 못 미치므로 짧게 전진해 정렬한 뒤 자이로 기준 오른쪽 90도 회전한다. 현재 시뮬레이터 초기값은 모터 명령 160으로 300 ms 전진이며, 실제 센서와 회전 중심 간 거리에 맞춰 다시 조정한다.

```text
weights = [-5, -3, -1, 1, 3, 5]
signal[i] = max(0, clamp(gainCorrectedRaw[i], 0, 700) - 50)
lineError = lowPass(sum(weights[i] * signal[i]) / sum(signal[i]))
correction = KpLine * lineError + KdLine * filteredDerivative(lineError)
           + KpHeading * (heading - targetHeading) + KdYaw * yawRate
```

시뮬레이터 IR 센서는 채널별 감도가 다르고, 읽기 함수는 2000 us에서 값을 제한한다. 따라서 검정/흰색 끝점만으로 보정하면 선이 두 센서에 걸칠 때 좌우 값이 서로 달라 한쪽으로 치우칠 수 있다. 선 추종에서는 `irRaw`의 흰색 기준을 뺀 뒤 포화 전 응답 범위 `{3038, 2250, 1800, 2363, 2475, 2700}` us로 보정한다. 강한 신호는 700에서 제한하고 작은 신호 50 이하는 제외한다. 이는 제공된 시뮬레이터에 맞춘 값이며 실제 센서에는 별도 보정이 필요하다.

중앙선 오차에는 시정수 25 ms의 필터를 적용하고, PD 제어에 목표 방향 오차와 자이로 회전 속도를 더해 급격한 조향을 줄인다. 현재 계수는 `LINE_KP=28`, `LINE_KD=0.35`, `LINE_HEADING_KP=2`, `LINE_YAW_KD=0.20`이다. 선을 다시 찾거나 상태가 바뀌면 필터를 초기화하여 이전 상태의 오차가 조향에 섞이지 않도록 한다. 구간 2의 기본 모터 명령은 220이며 선에서 벗어나면 감속한다.

- 검은 선이 오른쪽 센서에 치우치면 오른쪽으로 회전한다.
- 검은 선이 왼쪽 센서에 치우치면 왼쪽으로 회전한다.
- 잠깐 선을 잃으면 자이로 목표 방향으로 감속 직진한다. 350 ms 넘게 보이지 않으면 종료 조건을 만족하는 복귀 말기인지 확인하고, 그 외에는 오류 정지한다.
- 구간 1과 구간 2는 검은색 패턴이 다르므로 서로 다른 제어 함수와 계수를 사용한다.

완료 기준: 장애물을 제외한 구간 2의 가운데 선을 5회 연속 이탈 없이 추종한다.

### 5.5. 5단계: 장애물 감지 및 통과

시뮬레이터 및 제공 코드와 맞추기 위한 초음파 센서 연결은 다음과 같다.

- `TRIG = D6`
- `ECHO = D3`

파란 고정 상자는 중앙선 양옆에 있으므로 중앙선을 정밀하게 추종하여 통과한다. 제공된 시뮬레이터의 충돌 모델을 다시 확인한 결과, 상자 안쪽 면의 x좌표는 174 cm와 210 cm로 간격은 36 cm이다. 로봇 충돌 반경은 6 cm이므로 정확히 가운데 있으면 좌우 여유가 각각 12 cm이다. 이전에 적은 16 cm는 구간 1의 차로 폭과 혼동한 수치이므로 정정한다. 실제 코스가 더 좁을 수 있으므로 실물 간격과 로봇 폭을 재고 별도로 검증해야 한다. 중앙선 위의 빨간 차단기는 필요할 때 정지하고 올라간 후 통과한다.

1. 초음파 거리가 정지 임계값보다 작아지면 즉시 감속하고 정지한다.
2. 초음파 중앙값 필터에는 반응 지연이 있으므로 실제 제동거리를 고려해 임계값을 정한다.
3. 장애물이 올라가 거리가 충분히 멀어진 상태가 여러 번 연속 측정되면 다시 출발한다.
4. 정지 임계값과 재출발 임계값을 다르게 두어 경계값 부근에서 반복 정지하는 현상을 막는다.
5. 이미 열려 있더라도 차단기 앞의 대기 위치에서는 정지한다. 초음파로 닫힘을 한 번 확인한 뒤 다시 열리는 것을 감지하여 출발한다. 열린 상태의 거리만으로 남은 개방 시간을 판단하지 않는다.

열려 있는 차단기는 초음파로 위치를 알기 어려우므로, 모터 명령과 경과 시간으로 구간 내 이동거리를 추정하여 대기 위치를 잡는다. 시뮬레이터의 최고 속도 52 cm/s, 데드밴드 명령 48, 모터 응답 시정수 0.07초, 오른쪽 모터 이득 0.97을 사용한다. 이 값은 엔코더 측정값이 아닌 모델 추정치다.

| 구간 | 이동거리 추정의 시작 | 첫 차단기까지 거리 | 두 번째 차단기까지 거리 |
| --- | --- | ---: | ---: |
| 출발 방향 | 중앙선 진입 90도 회전 완료 | 64 cm | 128 cm |
| 복귀 방향 | 패드를 벗어나 RETURN에 진입 | 52 cm | 116 cm |

각 차단기 예상 위치의 27 cm 앞에서 정지 명령을 내린다. 정지 상태에서 초음파 거리가 32 cm 미만이면 닫힘을 확인한 것으로 기록하고, 이후 38 cm 초과가 120 ms 유지될 때 출발한다. 파란 상자도 초음파 원뿔 안에 들어갈 수 있으므로 이 임계값은 해당 대기 위치에서 관측한 다음 장애물 거리와 구분되도록 정했다. 통과 속도는 가운데 선 기본 명령 220이다. 예상 위치 이전에 11 cm 미만의 장애물이 감지되면 별도로 정지하며, 이 경우에는 19 cm 초과가 유지될 때 재출발한다.

차단기 대기 상태는 14초를 넘으면 오류 정지한다. 실제 환경에서는 추정 이동거리 오차와 센서 필터 지연, 제동거리, 차단기의 높이·주기를 모두 다시 검증해야 한다.

시뮬레이터 차단기는 8초 주기로 상승 1초, 열림 3초, 하강 1초, 닫힘 3초를 반복하며 두 차단기의 위상은 반 주기 어긋난다. 두 차단기의 간격은 64 cm이다. 지나치게 낮은 속도로 접근·통과하면 하강 도중 충돌할 수 있다.

완료 기준: 승강식 장애물의 여러 주기를 시험하여 10회 연속 충돌 없이 정지하고 재출발한다.

### 5.6. 6단계: 체크포인트 판별

체크포인트는 검은 테이프가 아니라 회색 패드다. 시뮬레이터 반사율 설정은 0.45이며, 센서별 이득과 검정 측정값의 2000 µs 잘림 때문에 정규화 값도 센서마다 다르다. 얇은 중앙선과 구분하기 위해 다음 조건을 조합한다.

- 대부분의 센서와 양끝 센서가 흰 바닥보다 높은 값을 보인다. 현재 초기값은 6개 중 5개 이상이 430 초과이고 양끝은 모두 350 초과이다.
- 이 패턴이 80 ms 이상 유지된다.
- 현재 상태가 `OUTBOUND`이고 두 차단기의 대기·해제 절차가 끝났다.

패드 깊이는 시뮬레이터에서 약 32 cm이며 뒤에 경계선이 있다. 패드 패턴이 처음 보이면 기본 명령을 110으로 낮추고, 80 ms 연속 확인 후 `ENTER_PAD`로 전환한다. 앞쪽 IR 센서가 차체 중심보다 먼저 패드에 닿으므로, 패드 확정 시점부터 모델 추정 거리 5.5 cm만 추가 전진한다. 이후 `PAD_STOP`에서 양쪽 모터 명령을 0으로 700 ms 유지한 뒤 유턴한다. 정지는 `millis()`로 관리하여 그동안 센서 갱신과 사용자 버튼 중지를 계속 처리한다. 패드 진입이 2초를 넘으면 오류 정지한다.

이전 구현은 명령 155로 500 ms 전진한 직후 유턴하여 전진 속도가 남아 있었다. 변경 후에는 패드 앞 경계에서 중심이 약 2 cm 들어간 위치에 멈추고 회전하도록 하였다. 현재 임계값 방식은 ‘회색임’을 단독으로 증명하는 검출기가 아니므로, 실제 패드 측정값과 구간 상태를 함께 사용하여 오인식을 확인한다.

완료 기준: 체크포인트 진입을 5회 연속 인식하고, 가운데 선이나 그림자에서는 잘못 인식하지 않는다.

### 5.7. 7단계: 유턴

시뮬레이터는 LSM6DS33(주소 0x6B)와 LIS3MDL(0x1E)을 제공한다. 현재 구현은 LSM6DS33의 z축 각속도를 적분하여 진입 90도 회전과 유턴 180도 회전을 처리한다. LIS3MDL은 사용하지 않는다. 정지한 `WAIT`에서 약 2.5초 동안 자이로 편향을 보정한 뒤 버튼 시작을 허용한다.

우선순위:

1. 실제 Zumo의 IMU 모델·주소·축 방향을 확인하고 해당 센서 드라이버로 약 180도 회전을 측정한다. 현재 코드는 LSM6DS33만 지원한다.
2. 방향 센서를 사용하기 어렵다면 최소 회전 시간 동안 제자리 회전한 뒤 IR 센서가 복귀 방향의 가운데 선을 찾을 때까지 저속으로 회전한다.
3. 시간만으로 회전 종료를 결정하는 방식은 배터리와 바닥 마찰에 따라 달라질 수 있으므로 최종 수단으로 사용한다.

완료 기준: 체크포인트에서 5회 연속 복귀 방향의 선을 정상적으로 다시 찾는다.

### 5.8. 8단계: 복귀와 위쪽 출구 판별

체크포인트에서 유턴한 뒤 구간 2만 반대 방향으로 주행한다.

1. `RETURN`에서 가운데 선과 장애물 조건을 다시 처리한다.
2. 구간 1과 합류했던 위치에서도 중앙선을 따라 위로 직진한다.
3. 시뮬레이터 중앙선은 도면 y=20에서 끝나며 별도의 결승 테이프는 없다. 충분히 복귀 주행한 뒤 선이 사라지는 것을 종료 단서로 사용한다.
4. `FINISH`로 전환해 양쪽 모터를 0으로 설정한다.

현재 구현은 복귀 중 두 차단기의 대기·해제 절차를 모두 마치고, 추정 복귀 이동거리가 205 cm 이상이며, 차단기 대기를 제외한 전진 시간이 7초 이상일 때 종료 판정을 허용한다. 여기에 방향 오차 10도 미만, 중앙선 미검출 350 ms 초과 조건이 함께 만족되어야 한다. 복귀 초반 및 추정 거리 180 cm 부근에서 선 입력을 제거하는 오류 주입 시험에서는 완주로 처리하지 않고 정지하였다. 다만 이동거리는 모델 추정치이므로 실제 코스의 종료 표식과 센서 패턴을 확인하여 최종 조건을 정한다.

완료 기준: 구간 2 위쪽 종료선을 통과하고 5회 연속 정지한다. 중간 선 이탈은 완주가 아니라 오류로 처리한다.

### 5.9. 9단계: 전 구간 통합

1. 부분 구간을 확인한 뒤 90초 시간 예산 안에서 전체 상태 전환 순서를 시험한다.
2. 각 상태 진입 시 시리얼에 상태 이름을 한 번 출력한다.
3. 실패한 구간과 센서값을 기록하여 해당 상태만 수정한다.
4. 완주가 안정화된 뒤 `BASE_SPEED`, 정지 거리, 제어 계수를 조금씩 조정한다.
5. 한 번에 여러 값을 바꾸지 않고 변경 전후 결과를 기록한다.

완료 기준:

- 시뮬레이터 전 구간 5회 연속 완주
- 실제 코스 전 구간 3회 연속 완주
- 한 번의 주행 시간이 1분 30초 미만
- 로봇 접촉, 코스 이탈, 장애물 충돌 없음

## 6. 시뮬레이터 시험 절차

1. PlatformIO에서 프로젝트를 빌드한다.
2. `.pio/build/uno/firmware.hex`를 `simulator-1.html`의 firmware 상자에 넣는다.
3. 로봇을 정지 상태로 두고 시리얼의 `READY`를 확인한 뒤 `User button` 또는 키보드 `B`를 눌러 출발한다.
4. 코드를 다시 빌드할 때마다 새 `firmware.hex`를 다시 넣는다.
5. IR 값, 초음파 거리, 시리얼 상태 출력, 실시간 점수를 함께 확인한다.
6. 로봇 위치를 바꿔 시험할 때에는 시작 전에 드래그하고, 회전은 `Shift+드래그`를 사용한다.

시뮬레이터 창이 숨겨지면 실행이 일시 정지된다. 시뮬레이터 결과는 실제 로봇과 완전히 같지 않으므로 논리 검증과 초기 계수 탐색 용도로 사용한다.

## 7. 시리얼 디버깅 계획

모든 반복문에서 출력하면 제어 주기가 느려질 수 있으므로 현재 구현은 250 ms 간격으로 필요한 값만 출력한다.

권장 출력 항목:

```text
ms,state,phase,heading,cm,ir0,ir1,ir2,ir3,ir4,ir5,left,right,travel_cm,gate
```

상태가 바뀔 때에는 별도로 다음과 같이 출력한다.

```text
state: LANE
state: OUTBOUND
state: BARRIER
```

이 기록은 문제 원인 분석과 보고서의 결과 설명에 함께 사용할 수 있다.

## 13. 실제 회로 연결 안내

### 13.1. 적용하는 로봇 구성

현재 코드와 아래 안내는 Arduino Uno R3를 꽂는 Zumo Shield 및 6채널 Zumo Reflectance Sensor Array를 기준으로 한다. 사용자는 Zumo 키트를 직접 조립해야 한다고 확인하였다. 실드 버전과 실제 포함 부품은 아직 확인되지 않았다. 차체, 모터, 배터리 접점, 헤더 납땜부터 진행해야 하며 아래의 추가 센서 배선만으로 조립이 완료되는 것은 아니다. [Pololu 조립 안내](https://www.pololu.com/docs/0J57/2.b)

조립된 구성에서는 모터 드라이버, 사용자 버튼, IMU가 실드에 연결되어 있고, 전용 IR 센서 배열은 앞쪽 커넥터로 신호와 전원을 연결한다. Uno는 실드의 지정 헤더에 결합한다. [Zumo Shield 안내](https://www.pololu.com/docs/0J57/all), [IR 센서 연결](https://www.pololu.com/docs/0J57/2.c)

미조립 키트의 진행 순서:

1. 차체, 좌우 기어모터 2개, 구동 바퀴·후륜 바퀴·트랙, Zumo Shield, 절연 스페이서, 배터리 접점, Uno, IR 센서 배열이 있는지 확인한다. 제품에 따라 모터와 IR 센서 배열은 별도 구성일 수 있다. 실드에 이미 조립된 스위치·버튼은 중복 장착하지 않는다.
2. Uno와 결합할 실드 헤더를 정렬하고 납땜한다. 미장착 스위치·버튼 및 필요한 커넥터도 버전에 맞게 조립한다. 전원과 배터리는 분리한 상태로 작업한다.
3. 모터 축에 구동 바퀴를 장착하고 각 모터의 두 단자에 리드선을 납땜한다. 표준 조립 설명에서는 모터의 + 단자가 차체 앞쪽을 향하도록 배치한다.
4. 차체에 모터, 절연 스페이서, 실드를 순서대로 장착하고 모터 리드선을 실드의 각 모터 전용 납땜 위치에 연결한다. 이 선은 Uno D7~D10에 직접 연결하는 것이 아니다.
5. 배터리함 접점을 배치하고 실드로 올라오는 두 접점을 지정 위치에 납땜한다. 후륜 바퀴와 트랙을 장착한다. 배터리는 배선·조립을 마친 후 배터리함 극성 표시에 맞춰 넣는다.
6. IR 센서 배열용 커넥터를 조립하고 센서가 바닥을 향하도록 장착한다. Uno용 LEDON 점퍼는 D2를 사용한다. 커넥터 방향은 해당 보드의 실제 사진과 제조사 조립 그림을 대조한다.
7. Uno를 실드 헤더에 결합하고 HC-SR04 네 선을 아래 표대로 연결한다. 금속 부품이나 잘라내지 않은 납땜 리드가 다른 기판·모터 외함과 닿지 않게 정리한다.

표준 키트에는 인두·납 등의 납땜 도구와 적절한 드라이버/육각렌치가 필요하다. 납땜 자리의 정확한 좌표나 헤더 방향은 실드 버전과 실제 조립 상태를 확인한 뒤 안내한다. [공식 준비물](https://www.pololu.com/docs/0J57/2.a), [공식 조립 순서와 사진](https://www.pololu.com/docs/0J57/2.b)

### 13.2. 직접 추가할 HC-SR04 배선

배선할 때에는 Zumo 전원 스위치를 OFF로 하고 USB도 분리한다. 센서의 왼쪽·오른쪽 위치를 외워 연결하지 말고 PCB의 VCC, TRIG, ECHO, GND 인쇄를 읽어 연결한다.

| HC-SR04 핀 | 연결할 Uno 신호 | 역할 |
| --- | --- | --- |
| VCC | 5V | 센서 전원 |
| GND | GND | 공통 접지 |
| TRIG | D6 | 초음파 측정 시작 펄스 |
| ECHO | D3 | 반사 신호 펄스 입력 / 외부 인터럽트 |

TRIG D6와 ECHO D3는 제공 `include/zumo.h` 및 시뮬레이터의 배치와 일치한다. HC-SR04는 5V 전원을 사용한다. VCC를 배터리 전압인 VBAT나 Uno VIN에 연결하지 않는다. [HC-SR04 제조사 데이터시트](https://www.elecfreaks.com/download/HC-SR04.pdf)

실드가 Uno의 소켓을 차지하고 있다면 같은 신호에 연결된 접근용 헤더/패드를 사용한다. D3와 D6는 Zumo의 앞쪽 확장 커넥터에 나오지 않으므로, 앞쪽 빈 구멍을 임의로 D3/D6로 간주하면 안 된다. 실제 핀을 꺼낼 위치는 로봇의 헤더 구성과 인쇄를 보고 정한다. [확장 핀 설명](https://www.pololu.com/docs/0J57/3.b)

작은 브레드보드를 사용할 경우 Uno 5V를 + 전원 레일에, GND를 - 레일에 연결하고, 센서 VCC/GND를 각각 같은 레일에 연결한다. TRIG와 ECHO는 서로 분리된 신호 배선으로 D6/D3에 연결한다. 네 센서 핀이 브레드보드 내부의 같은 연결 묶음에 들어가지 않도록 한다. 브레드보드는 필수 부품이 아니며, 맞는 점퍼선으로 직접 연결하고 센서를 별도 고정해도 된다.

### 13.3. 실드 내부 연결과 충돌 확인

아래 표는 이미 실드/전용 센서 보드에서 연결되는 신호를 설명한 것이다. 조립되어 있는 회로에 같은 전선을 추가하라는 뜻이 아니다.

| 기능 | Uno 핀 |
| --- | --- |
| 오른쪽 모터 방향 / PWM | D7 / D9 |
| 왼쪽 모터 방향 / PWM | D8 / D10 |
| 사용자 버튼 | D12 |
| IR S0~S5: 로봇이 전진하는 방향을 기준으로 왼쪽부터 | D4, A3, D11, A0, A2, D5 |
| IR 발광 제어 LEDON | D2 |
| 내장 IMU SDA / SCL | A4 / A5 (Uno R3의 SDA/SCL과 같은 신호) |

모터는 실드의 모터 드라이버 출력에 연결한다. 위 D7~D10은 드라이버 제어 신호이며 모터 전선을 Uno 핀에 직접 연결하는 배선이 아니다. [공식 핀 배치](https://www.pololu.com/docs/0J57/5)

Uno에서 부저 BZ를 D3에 연결하는 328P 점퍼가 연결되어 있으면 해제하여 ECHO 입력과 공유하지 않게 한다. 뽑는 점퍼캡인지 납땜 연결인지 먼저 확인하고, 기판의 임의 패턴을 자르지 않는다. IMU용 SDA/SCL 연결은 유지한다. [점퍼 설명](https://www.pololu.com/docs/0J57/3.c)

전용 IR 센서 배열의 LEDON 점퍼는 Uno 기준 D2 위치를 사용한다. 센서가 로봇 앞쪽에서 바닥을 향하고 모든 센서가 비슷한 높이에 있도록 장착한다. [IR 센서 조립·LEDON 안내](https://www.pololu.com/docs/0J57/2.c)

### 13.4. 전원과 초음파 센서 장착

표준 Zumo Shield 차체는 AA 배터리 4개를 배터리함에 넣어 사용한다. 배터리는 실드의 모터 전원과 Uno 전원을 공급한다. USB만 연결하고 실드 스위치가 OFF이면 Uno와 센서는 켜질 수 있어도 모터 전원은 공급되지 않는다. 실드에서 전원을 공급받는 동안 Uno VIN이나 원형 전원잭에 별도 전원을 함께 연결하지 않는다. [공식 전원 설명](https://www.pololu.com/docs/0J57/3.a)

초음파 센서는 로봇의 정면을 향하도록 고정하고, 기울어지거나 선이 트랙에 닿지 않도록 한다. 시뮬레이터는 센서 중심 높이 9 cm, 로봇 중심보다 5 cm 앞을 가정한다. 실제 장착 높이와 앞뒤 위치를 기록하고, 낮아진 차단기를 감지하면서 열린 차단기에는 충분한 통과 공간이 있는지 확인한다. 이 위치 차이는 정지 거리와 차단기 대기 위치 보정에 반영해야 한다.

빨간 차단기를 움직이는 서보는 코스 쪽 장치이며, 현재 로봇에 연결하는 부품은 아니다.

### 13.5. 실제 주행 전 코드 설정

현재 main.cpp는 `SIMULATION = true`이며 실물 보정값은 아직 임시값이다. 회로를 연결했다고 시뮬레이터 설정으로 바로 주행 검증이 끝나는 것은 아니다.

1. 실드 버전을 확인한다. v1.3의 LSM6DS33은 현재 드라이버 대상이다. v1.2는 L3GD20H 자이로를 사용하므로 드라이버를 바꿔야 하며, 초기 실드는 자이로가 없다. [IMU 버전 안내](https://www.pololu.com/docs/0J57/3.d)
2. 실제 흰 바닥·검은 테이프·회색 패드의 IR 원시값을 기록하고 REAL_WHITE/REAL_BLACK 및 판별 임계값을 정한다.
3. 모터의 전진 방향, 좌우 편차, 속도와 제동거리 및 모델 기반 이동거리 추정값을 실측으로 맞춘다.
4. 보정값이 준비되면 SIMULATION을 false로 하고 REAL_CALIBRATION_READY를 true로 설정하여 다시 빌드한다. 플래그 변경만으로 실물 보정이 이루어지는 것은 아니다.
5. 처음에는 트랙이 바닥에 닿지 않도록 받침대에 올려 모터 방향과 사용자 중지를 확인한 뒤, 코스에서 낮은 속도로 부분 구간을 시험한다.

USB로 정지 상태 센서값을 확인할 때 시리얼 모니터는 115200 baud를 사용한다. 현재 로그의 IR 열은 정규화 값이며 실물 보정을 위한 원시 irRaw 값은 별도로 출력하여 측정해야 한다.
